### C3-R1-1 - P1 - A cancellation spanning requeue is lost

VERIFIED SOURCE + EXECUTED FIXTURE. `core/src/main/kotlin/dev/pampa/pampanotes/core/repo/TranscriptionRepository.kt:478-482` performs `cancelIfQueued`, then `requestCancelIfRunning`, without a transaction or retry. `core/src/main/kotlin/dev/pampa/pampanotes/core/db/Daos.kt:693-701` excludes QUEUED from the second statement. The corrected requeue at `Daos.kt:772-779` only recognizes cancellation already recorded as CANCEL_REQUESTED.

Exact legal interleaving, after the watcher at `app/src/main/kotlin/dev/pampa/pampanotes/work/TranscriptionQueueWorker.kt:545-547` has exited:

1. Job is TRANSCRIBING. requestCancel.cancelIfQueued updates 0 rows.
2. quotaWait/requeueUntil runs requeue: updates 1 row, job becomes QUEUED, phase quota.
3. requestCancel.requestCancelIfRunning updates 0 rows because QUEUED is excluded.
4. requestCancel returns successfully. Job remains QUEUED, finishedAt null, activeForSession true, nextQueued true.

The existing four source-extracted SQLite tests pass. The independent assertion that cancellation must finish CANCELLED fails with actual QUEUED. This is production DAO SQL against the generated schema 15, not a hand-written replacement SQL query and not Room/WorkManager execution. The state can resume at expiry without any further user action; restarting does not repair the missing cancellation intent. The worker's `quotaWait` at lines 482-489 cannot observe an intent that was never stored. The existing tests at `core/src/test/python/test_cloud_requeue.py:44-61` cover cancellation before or after requeue, but not the gap inside requestCancel.

Required correction: make cancellation and transitions from running to queued coordinate atomically; add this interleaving to regression coverage. Fix must terminate cancellation without restart.

Evidence: review_c3.py, sqlite-results.txt, cancellation-trace.json in this report directory.

An initial exploratory read-only-attribute attempt did not reproduce a write failure; the final locked-file fixture did and is separately preserved.

Required correction: fail before upload when the work-plan identity cannot be durably established; preserve completed paid results on that failure rather than treating them as disposable under an unverifiable plan.
