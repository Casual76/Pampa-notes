## Confirmed finding C2-R1-01: legacy OpenRouter queue loses its selected folder model

Severity: **P1 / high; mandatory correction**. Trigger: upgrade with a not-yet-started OpenRouter transcription row, `state=QUEUED`, `model=null`, `attempts=0`, `optionsJson=null` (or old options lacking the new plan fields), no work signature, an allowed folder policy selecting model A, and a different valid global OpenRouter model B.

Evidence and reproduction:

1. At the base commit, enqueue saved `model=null`; OpenRouter binding supplied a preparation callback that resolved `spending.policyForSession(...)` and copied `policy.model ?: request.model`. Thus the existing folder selection governed first dispatch. Read-only `git show ea4e0a2:core/src/main/kotlin/dev/pampa/pampanotes/core/repo/TranscriptionRepository.kt`, OpenRouter branch of `bind`, verifies this historical behavior.
2. In the frozen revision, `pinForRun` (`TranscriptionRepository.kt:234-252`) finds no existing model or work signature for the described row, then calls `modelAtEnqueue(job.provider, settings, options.overrides)` at line 250. It never obtains/passes the folder policy model.
3. `modelAtEnqueue` declares `folderModel: String? = null` and uses `overrides?.model?.takeIf(String::isNotBlank) ?: folderModel ?: settings.openRouterTranscriptionModel` for OpenRouter (`226-230`). Therefore it pins B rather than A. If the global model is empty, the worker instead fails at `TranscriptionQueueWorker.kt:370`, despite the configured folder model.
4. No later stage restores A: `CloudSpending.beforeUpload` retains `request.model` (`core/.../spending/CloudSpending.kt:130-160`), while the current OpenRouter binding no longer has the old preparation callback (`TranscriptionRepository.kt:605-608`). A valid B passes worker validation and is sent as the model (`OpenRouterTranscriptionProvider.kt:73-80`).

Executed fixture: `python -B review_c2.py`, function `selection_counterexample`, extracts the actual OpenRouter null-coalescing expression and confirms the legacy call omits `folderModel`. With `fixture/folder-selected` configured for the folder and `fixture/global-selected` globally, it produces the latter. **This executes the extracted selection expression, not Kotlin/Room/WorkManager.** The finding rests on the complete source path as well as this limited fixture. No inference request was made; identifiers are arbitrary fixture strings. For actual dispatch reproduction, use any two supported STT IDs.

Requirement consequence: the explicit request to review pre-upgrade queued jobs and preserve the exactly chosen automatic model is not satisfied. Different model selection is confirmed; different cost/quality/charging is not inferred.

Suggested correction boundary (no fix made): when first pinning a legacy cloud row with no established model/signature, resolve the allowed folder policy and pass its model using the same precedence as new enqueue. Keep already-pinned models and explicit per-job overrides authoritative. Add a legacy-row regression with different folder/global models, then change defaults and retry to verify the recovered choice remains fixed.
